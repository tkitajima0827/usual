# 予実管理システム（MVP）

顧客ごとの単年度計画・中期経営計画をもとに予実管理を行うソフトウェアの試作。
現段階は「単一顧客の単年度PL計画（勘定科目ごとの計算方式選択）」に範囲を絞った
検証版です。

## 技術スタック

- Next.js (App Router) + TypeScript + Tailwind CSS
- PostgreSQL + Prisma ORM（v7, driver adapter方式）
- Vitest（計算エンジンの単体テスト）

## セットアップ

```bash
# 1. PostgreSQL を用意し、.env の DATABASE_URL を設定
cp .env.example .env  # なければ手動で作成

# 2. 依存パッケージのインストール
npm install

# 3. マイグレーション適用
npx prisma migrate dev

# 4. テストデータ投入（顧客1社・過去2期分の実績・FY2026計画をシード）
npm run db:seed

# 5. 開発サーバー起動
npm run dev
```

`.env` の例:

```
DATABASE_URL="postgresql://USER:PASSWORD@localhost:5432/yozan_kanri?schema=public"
```

## データモデル（`prisma/schema.prisma`）

- `Client`: 顧客（期首月・税込/税抜経理の別）
- `User`: 事務所スタッフ／顧客ユーザー（`UserRole`で権限区分。今回は認可ロジック未実装）
- `Account`: 顧客ごとの勘定科目（PL/BS/CFの`statement`区分、PLは`plCategory`で集計グループ化）
- `MonthlyActual`: 勘定科目ごとの暦月実績（MF会計等からの取込を想定。現状はシードデータのみ）
- `FiscalYear`: 顧客の会計年度（期首年月で12ヶ月を定義）
- `PlanEntry` / `PlanDirectValue`: 年度計画における勘定科目ごとの計算方式設定と直接入力値

## 計算エンジン（`src/lib/calc/engine.ts`）

DBに依存しない純粋関数として実装。4つの計算方式に対応:

- **前年同額**: 対象月の12ヶ月前（実績）をそのまま使用
- **科目連動**: 連動先科目の同月値 × 指定割合（%）。LINKED科目間の依存関係は月ごとにトポロジカルソートして解決し、循環参照はエラーとして報告
- **直接入力**: ユーザーが月ごとに入力した値
- **過去平均**: 対象月の直前12ヶ月の平均。年度開始前は実績、年度に入ってからは同一年度内で既に計算済みの値を含めたローリング平均として算出

実績データの欠落やLINKED設定の不備は例外を投げず、0円として扱った上で警告メッセージを返す設計にしている（実データは欠測がありうるため）。

## 実績データの取込（`src/lib/import/actuals.ts`）

MFクラウド会計など外部ソースから月次実績を取り込むための、ソース非依存の正規化レイヤー。

- `ActualImportRow`（`{ accountCode?, accountName, statement?, plCategory?, year, month, amount }`の配列）を受け取り、
  `importMonthlyActuals()` が勘定科目の自動作成（未登録科目はコード未設定でも科目名から安定コードを生成）と
  `MonthlyActual` の upsert（再実行しても安全）を行う。
- CSVエクスポート・公式API・MCP経由のいずれから取得したデータも、まずこの形式に変換してから渡す想定。
  ソースごとの差異（列名・APIレスポンス構造）を吸収するアダプタは、フォーマットが確定次第追加する。
- 動作確認用CLI: `npm run import:actuals -- --client "顧客名" --file <正規化JSON>`
  （サンプル: `fixtures/mf-import-example.json` で動作検証済み。新規科目作成・upsertの冪等性を確認済み）

### MFクラウド会計アダプタ（`src/lib/import/mfCloudAdapter.ts`）— 実装済み・実データで検証済み

「マネーフォワード クラウド会計」MCPコネクタが本セッションで有効化されたため、当面は以下の運用で連携する
（事業者切替が容易になり次第、公式API(OAuth2)へ移行予定。MCP接続は対話セッション前提のため、Claudeが
手動またはRoutine（定期実行）でデータを取得し、DBへ流し込む運用になる）:

1. Claudeが `mfc_ca_getAccounts`（勘定科目マスタ）と `mfc_ca_getReportsTransitionProfitLoss`
   （月次推移表PL、`type=monthly`）をMCP経由で取得し、生JSONをファイルに保存する
   （実データのため git管理外のスクラッチ領域に保存し、リポジトリにはコミットしない）。
2. `convertMfTransitionPlToActualImportRows()` が、取得したJSON（勘定科目ツリー構造）を
   `ActualImportRow[]` に変換する。変換ロジック:
   - 勘定科目マスタの `account_group`/`category` を本システムの `PLCategory` にマッピング
     （`NET_SALES→REVENUE`、`COST_OF_PURCHASED_GOODS→COGS`、`SELLING_GENERAL_AND_ADMINISTRATIVE_EXPENSES→SGA` 等）
   - `type: "account"` ノードの値をそのまま使用し、`sub_account`（補助科目）の内訳には個別には立ち入らない
     （親科目の値に既に合算されているため。補助科目単位の取込は本システムのデータモデルが対応するまでの将来対応）
   - `settlement_balance`（決算整理仕訳）は会計期間の最終月に合算する
   - `financial_statement_type: "BALANCE_SHEET"` の科目、勘定科目マスタに見つからない科目、
     未対応カテゴリの科目はスキップまたは警告付きで分類未設定として取り込む
3. `scripts/import-mf-transition-pl.ts` で `importMonthlyActuals()` に渡しDBへ反映する。

実際に自社（ステラリンクスグループ）の2023〜2026年度のMFクラウド会計データで動作検証済み。
37勘定科目・1,500件の月次実績を取り込み、MF側の年間合計（`total`列）と1円単位で一致することを確認した
（決算整理仕訳を含む減価償却費のケースも含む）。単体テストは `src/lib/import/mfCloudAdapter.test.ts` を参照。

CSVエクスポートや公式APIなど、別のデータソースを使う場合も `ActualImportRow[]` に変換するアダプタを
追加すれば同じ `importMonthlyActuals()` で取り込める。

### 他顧客への展開の検証

MCPの接続事業者を実際の顧客（アイシンクメディカル株式会社）に切り替えて、コード変更なしで
同じ手順（`create-client.ts` → `import-mf-transition-pl.ts`）が動くことを確認済み。この顧客は
3月始まり・税抜(内税)経理・42勘定科目と、ステラリンクスグループとは会計年度・経理方式・勘定科目
体系のいずれも異なるが、正規化レイヤーのおかげでスクリプト側の変更は不要だった。FY2022〜FY2026の
5期分（約1,900件の月次実績）を取込み、MF側の年間合計と1円単位で一致することを確認済み。

新規顧客の単年度計画を素早く用意するための汎用CLIも追加した:
`scripts/create-default-plan.ts` — 指定した会計年度の全PL科目を「過去平均」で初期設定する
（実績さえ取り込まれていればどの顧客にも使える）。その後、ブラウザの編集UIで固定費性の科目を
前年同額に、原価科目を科目連動に、といった調整を行っていく運用を想定。

### 過去平均の限界（データ不足時の挙動）

実績データの欠落期間が長い場合、過去平均（過去12ヶ月平均）は計画年度内で既に算出済みの値だけで
算出されることになり、数学的にある時点から値が収束して横ばいになる（同じ値の移動平均を取り続けると
平均が変化しなくなるため）。これはバグではなく「使えるデータが乏しい」ことの正しい反映だが、
該当する科目には⚠警告アイコンが表示されるので、参照する側はどの程度実績に基づいた数値かを確認できる。

## 税額概算（消費税・法人税）— `src/lib/tax/`

bixidの「申告データ登録」画面に相当する機能。DBに依存しない純粋関数として
`src/lib/tax/estimate.ts` に実装し（単体テストは `estimate.test.ts`）、
`getPlanViewModel()` が計画値（実績優先後の値）から必要な集計を行って呼び出す。

- **法人税**: 実効税率方式（bixidと同じ簡易方式）。
  `課税所得 = max(0, 税引前当期純利益 − 繰越欠損金)`、`概算年税額 = 課税所得 × 実効税率`。
  個別税目（法人税・住民税・事業税）には分解せず、単純化した概算値として扱う。
- **消費税**: 本則課税による概算。勘定科目ごとに消費税の課税区分
  （`Account.consumptionTaxCategory`: 課税/非課税/対象外）を持たせ、
  `課税売上高（REVENUE科目の「課税」区分の合計） − 課税仕入高（COGS+SGA科目の「課税」区分の合計）` に
  消費税率を乗じて概算する。課税区分の初期値は科目名からのヒューリスティック推定
  （`classifyConsumptionTax()`。給与・租税公課・減価償却費などは「対象外」、支払利息・保険料などは
  「非課税」、それ以外は「課税」）で、MFクラウド会計取込／実績インポート時の新規科目作成にも
  適用される。誤判定は各科目の「編集」から手動で上書き可能。
- **中間納付額**: 前期の年間確定税額（`TaxSettings.priorYearCorporateTaxAnnual` /
  `priorYearConsumptionTaxAnnual`、bixidの「申告データ登録」相当の入力欄）の1/2という
  簡便な近似値。仮決算による中間申告や少額不要基準は考慮していない。
- 会計年度ごとの設定（実効税率・繰越欠損金・消費税率・前期税額）は `TaxSettings` モデルに保持し、
  プラン画面の「税額概算」カードの「申告データ登録」ボタンから編集できる
  （Server Action `updateTaxSettings`）。

このためPLの計算区分を `EXTRAORDINARY_INCOME`（特別利益）/`EXTRAORDINARY_LOSS`（特別損失）/
`INCOME_TAXES`（法人税等）まで拡張し、経常利益の下に税引前当期純利益・当期純利益の小計行を追加した。

いずれもあくまで「概算」であり、軽減税率・簡易課税・別表調整・各種税額控除等は考慮していない
（実際の申告額とは異なる）。中小企業庁等の統計を用いた決算分析（財務診断・ライバル比較）は、
bixidのUI確認時に難易度を理由に見送りとした。

## 画面

- `/` : 顧客一覧
- `/clients/[clientId]` : 顧客の単年度計画一覧
- `/clients/[clientId]/plans/[fiscalYearId]` : 単年度PL計画（KPIカード・月次売上高推移グラフ・勘定科目別月次テーブル）
  各科目の「編集」ボタンから計算方式（前年同額/科目連動/直接入力/過去平均）・連動先科目・割合・
  直接入力値をブラウザ上で編集できる（Server Action `updatePlanEntry` で保存、保存後は自動的に
  再計算されたページが再表示される。科目連動・過去平均などは依存する他科目の値も含めてその場で
  再計算されるため、例えば売上高を編集すると連動している売上原価も追従する）。
  警告（実績データ不足など）がある科目名の横には⚠アイコンを表示し、ホバーで内容を確認できる。
  各科目の前期行・当期行はbixidの経営計画画面に倣い並べて表示し、月次売上高等の小計行の直下には
  黄系背景の構成比（対売上高%）行を表示する。月見出しには「実績確定済み」か「計画（未確定）」かを
  示す実/予バッジを付け、実績が判明している月はセル背景を薄く強調する。
  「税額概算」カードでは概算法人税額・概算消費税額・概算中間納付額（法人税/消費税）を表示し、
  「申告データ登録」から実効税率・繰越欠損金・消費税率・前期税額を編集できる。

## 今回のスコープ外（次フェーズ以降のロードマップ）

要件定義でいただいた項目のうち、以下は今回未実装。段階的に拡張する想定:

1. **5年間の中期経営計画（BS/PL/CF連動）** — 単年度計画を5期分つなげる仕組み、BS・CFの自動連動ロジック
2. **消費税・法人税の概算計算** — 実装済み（「税額概算」参照）。実効税率方式の法人税概算・本則課税の消費税概算・中間納付額の簡易試算に対応。軽減税率・簡易課税・個別税目への分解は対象外
3. **MFクラウド会計からのデータ取込** — MCP経由のアダプタを実装し実データで検証済み（「MFクラウド会計アダプタ」参照）。定期実行の自動化（Routine化）と、事業者切替が容易になった後の公式API(OAuth2)への移行は今後の課題
4. **複数顧客の集計・トレンド可視化ダッシュボード** — 全顧客の黒字化率・成長率などの集計グラフ
5. **売掛・買掛金の回収・支払サイト設定** — 標準サイトの初期設定＋相手先・売上分類ごとの個別例外設定（次の実装対象）
6. **認証・権限制御** — `User.role`によるロール設計はスキーマに用意済みだが、ログイン機能・権限チェックは未実装（誰でも編集できてしまう状態）
7. **事業者切替の自動化** — 実データ取込みのスクリプト自体は他顧客でもそのまま動くことを検証済み（「他顧客への展開の検証」参照）。ただしMCP側の事業者切替は依然手動（ブラウザでのアカウント選択操作）が必要で、複数顧客を自動的に順次同期する仕組みは未整備
8. **bixidのUI/UX詳細反映** — 実装済み。ユーザー提供のスクリーンショットをもとに、前期/当期比較行・実績/計画バッジ・構成比行・税額概算カードなどbixidの経営計画画面に倣ったUIへ反映した。ただし以下は範囲外とした:
   - **資金繰り（借入金ごとのCF管理）** — CF計画実装時にあわせて対応予定
   - **決算分析（財務診断・ライバル比較）** — 中小企業庁等の統計を使った同業種比較は難易度が高いため見送り
