# 有価証券損益管理システム

SBI証券の取引データ（約定履歴）をもとに、銘柄ごとに現物・信用取引を移動平均法で
原価計算し、実現損益・月末の時価評価損益を算出したうえで、MF会計インポート用の
仕訳CSV/Excelを生成する社内向けWebアプリです。事業者（テナント）は複数登録でき、
社内メンバーは事業者を切り替えて利用できます（社外ユーザーの招待機能はありません）。

## 主な機能

- **データ取込**: SBI証券「約定履歴照会」のエクスポート（.xlsx / .csv）をアップロードし、
  自動でパースします。
- **原価計算エンジン**: 現物・信用買建・信用売建をそれぞれ独立した移動平均法のロットとして
  管理し、現引・現渡（信用⇔現物の付け替え）も正しく処理します。詳細は
  `src/lib/engine/costEngine.ts` のコメントを参照してください。
- **仕訳生成**: 取引および月末評価から複式簿記の仕訳を自動生成し、
  `/journal` から MF会計インポート用の CSV / Excel をダウンロードできます。
- **月末時価評価**: 売買目的有価証券について月末単価を入力すると、帳簿価額との差額を
  有価証券評価損益として自動計上します。
- **ダッシュボード**: 指定月末の銘柄別残高・評価損益、期間を通じた月別推移グラフを表示します。
- **事業者切り替え**: 1ユーザーが複数事業者に所属可能。管理画面から事業者・会計期間・
  社内メンバーを管理できます。

## セットアップ

PostgreSQLが必要です（ローカルにインストールするか、Dockerなどで用意してください）。

```bash
npm install
cp .env.example .env   # DATABASE_URLを自分のPostgres接続先に、AUTH_SECRETをopenssl rand -base64 32などで生成して設定
npx prisma migrate dev
npm run db:seed              # 蛤覚合同会社 + 管理者ユーザー(初期パスワード changeme123)を作成
npm run db:seed:hamaguri     # 26.02月期の参考データ(2026年2月の実データ)を投入 (任意)
npm run dev
```

初回ログイン後、管理画面（`/admin`）からパスワードの再設定や社内メンバーの追加を行ってください。

## 開発フロー

1. `/admin` で会計期間・社内メンバー・事業者を作成する
2. `/opening-balance` で期首（または直近確定月末）の保有銘柄・株数・帳簿残高を登録する
   （前期末の残高証明書を参照）
3. `/import` で当月分の元データ（約定履歴）をアップロードする
   → 自動で原価計算・実現損益計算・仕訳作成まで実行されます
4. `/valuation` で当月末の株価を入力し、時価評価損益を計算する
5. `/journal` で仕訳を確認し、CSV/Excelをダウンロードして MF会計にインポートする
6. `/dashboard` で残高・評価損益の推移を確認する

## 本番環境へのデプロイ（Railway・非エンジニア向け手順）

社内メンバー全員が使えるようにするには、インターネット上のサーバーにこのアプリを
置く必要があります。ここでは [Railway](https://railway.app) というサービスを使う
手順を説明します（月額はデータ量にもよりますが数百〜2,000円程度が目安です）。

データの保存には PostgreSQL（Railwayの「Database」機能でボタン1つで追加できます）を
使います。SQLite用のVolume設定のような分かりにくい手順は不要です。

### 事前に用意するもの

- GitHubアカウント（このリポジトリにアクセスできるもの）
- 管理者として使うメールアドレスと、ログイン用パスワード（自分で決めてください。
  8文字以上）

### 手順

1. **Railwayにサインアップする**
   https://railway.app を開き、「Login」→「Login with GitHub」でGitHubアカウントを
   使って登録します。

2. **新しいプロジェクトを作成する**
   ダッシュボードで「New Project」→「Deploy from GitHub repo」を選び、
   このリポジトリ（`tkitajima0827/usual`）を選択します。

3. **アプリの場所（サブフォルダ）を指定する**
   このアプリは `webapp` というフォルダの中にあるため、作成したサービスの
   「Settings」タブにある「Root Directory」に `webapp` と入力して保存します。

4. **本番用のブランチにつなぐ**
   同じ「Settings」タブの「Branch connected to production」で、
   `claude/sbi-trading-pnl-app-4a06n2`（またはこのアプリの正式な本番ブランチ）を
   選択します。似た名前の別のブランチと間違えやすいので注意してください。

5. **データベース（PostgreSQL）を追加する**
   プロジェクトの全体図（四角いサービスの箱が並ぶ画面）で「+ New」または右クリック
   から「Database」→「Add PostgreSQL」を選びます。新しいデータベースの箱が
   追加されます。

6. **環境変数（設定値）を入力する**
   アプリ本体のサービス（`usual`という箱）の「Variables」タブを開き、
   以下を追加してください。

   | 変数名 | 値 |
   | --- | --- |
   | `DATABASE_URL` | 「Add Reference」から、手順5で追加したPostgresサービスの `DATABASE_URL` を参照として選択（自分で値を入力する必要はありません） |
   | `AUTH_SECRET` | ランダムな文字列（`openssl rand -base64 32` で生成するか、社内で管理している値を使用） |
   | `SEED_ADMIN_EMAIL` | 管理者として使いたいメールアドレス（例: 自分の会社のメール） |
   | `SEED_ADMIN_PASSWORD` | 管理者の初期パスワード（8文字以上。あとで画面から変更できません、社内メンバー作成機能から別アカウントを作るのがおすすめです） |

7. **公開する**
   アプリ本体のサービスの「Settings」タブの「Networking」→「Generate Domain」を
   押すと、`https://〇〇.up.railway.app` のようなURLが発行されます。ポート番号は
   自動入力されたままで構いません。これが社内メンバーに共有するアプリのURLです。

8. **デプロイを待つ**
   「Deployments」タブでビルドが進みます。緑色の「Active」になれば完了です
   （数分かかります）。初回起動時に自動でデータベースの準備と管理者アカウントの
   作成が行われます。

9. **ログインして社内メンバーを追加する**
   発行されたURLにアクセスし、手順6で設定したメールアドレス・パスワードで
   ログインします。画面右上の「管理」メニューから、社内メンバーを1人ずつ
   追加できます（メールアドレス・氏名・初期パスワードを入力するだけです）。
   追加されたメンバーにはURLとログイン情報を個別に伝えてください
   （招待メールは自動送信されません）。

### 更新の反映方法

このアプリのコードに変更が入ったとき（今後Claude Codeで機能追加した場合など）は、
GitHubの本番ブランチに変更がpushされると、Railwayが自動的に再ビルド・再デプロイします
（「Auto deploy」をEnableにしている場合）。手動作業は不要です。

### うまくいかないときは

- ビルドが失敗する場合は「Deployments」タブでログを確認してください。
- ログイン画面が真っ白/エラーになる場合は、`AUTH_SECRET` と `DATABASE_URL` が
  正しく設定されているか確認してください。
- `Deployments`タブの履歴に見覚えのないコミット（他の無関係な作業のもの）が
  表示されることがありますが、これはRailwayのサービスが過去に別のブランチへ
  つながっていた際の古い履歴が残っているだけで、実際のコード（GitHub上の該当
  ブランチの中身）には影響しません。心配な場合はGitHub上でブランチの内容を
  直接確認してください。

## データモデルの要点

- `Business` = 事業者（テナント）。`Membership` でユーザーと紐づけ、ADMIN/MEMBER の権限を持つ。
- `FiscalPeriod` = 会計期間（例: 26.02月期）。
- `OpeningBalance` = 会計期間開始時点（または直近確定時点）の現物・信用買建・信用売建の
  残高。信用買建と信用売建は別々のロットとして扱う。
- `Trade` = SBI証券の元データを正規化した取引明細（現物買/売、信用新規買/売、
  信用返済買/売、現引、現渡）。
- `CostLedgerEntry` = 移動平均法による原価台帳。取引ごとの残高・実現損益のスナップショット。
- `MonthEndPrice` / `Valuation` = 月末単価と評価損益。
- `JournalEntry` = 生成された仕訳（取引起因 / 評価起因）。

## 原価計算・仕訳のロジックについて

現引・現渡は「新規建て時と全く同一の約定単価で決済される」という実際の値動きを
実データで確認したうえで実装しています（信用側では損益ゼロ、現物側の平均原価との
差額でのみ実現損益を認識）。仕訳の勘定科目（信用取引未払金・担保差入有価証券・
借入有価証券・担保差入金・差入証拠金など）も、実際にMF会計へ登録されている
仕訳データの内容を解析して再現しています。詳細は `src/lib/engine/journalRules.ts`
のコメントを参照してください。

`prisma/seed-hamaguri-202602.ts` は蛤覚合同会社の2026年2月の実データ（元データ全42件、
2026年1月末時点の現物保有、2026/2/27時点の実際の株価）を投入する参考スクリプトです。
投入後の銘柄別実現損益・評価損益は、実際の「有価証券評価損益計算」シートの数値と
完全に一致することを確認済みです。2月中に決済されたが建玉が1月以前の信用ポジション
（寿スピリッツ・iFreeETF・宮地エンジニアリンググループ）についても、現引の約定単価
（建値と同一単価で決済される）や同日ロールオーバーの単価から原価を求めており、
ファイル冒頭のコメントに算出根拠を明記しています。
